# 多 Agent 开发工作流程

本文约定从需求到人工审查的协作流程。它是流程说明，不是独立技能入口；具体技能仍通过各自的 `SKILL.md` 定义。实际执行时遵守用户授权范围和环境权限。

## 流程概览

```text
requirements.md（需求）
      │
      ▼
Planner Agent（规划）
      ├── 仓库调查
      └── design.md + task.md
      │
      ▼
Generator Agent（实现）
      ├── 代码
      ├── 测试
      └── 数据迁移（需要时）
      │
      ▼
Evaluator Agent（评估）
      ├── 测试
      ├── 代码规范 / 类型检查
      ├── 浏览器验证
      └── 差异审查
      │
      ▼
人工判断 / 合并
```

## 1. 需求输入：requirements.md

记录问题背景、用户目标、需求范围、验收标准、限制和待确认事项。区分当前行为与目标行为，不把假设写成已确认需求。

本仓库可将已有的 `Agent_rules/changes/` 需求记录作为输入；不要求为了命名重复复制文档。需求、设计和任务文档应互相引用，并注明对应的需求记录。

## 2. Planner Agent：规划

**输入：** 需求文档、当前仓库、项目架构及前端/后端/数据库约束。

**任务：**

1. 只读调查仓库，定位入口、调用链、接口、数据模型和相关实现。
2. 区分已实现能力、待补齐能力与未知信息，给出证据路径。
3. 搜索相似代码，确定可复用部分、影响范围及必要的结构变更。
4. 设计实现方案和验证方式，识别需用户决定的事项。

**产出：**

- `design.md`：方案、模块职责、接口输入输出、数据关系、兼容性、迁移方案及必要取舍。
- `task.md`：有顺序和依赖关系的任务清单；每项包含目标、预计路径、完成标准和验证方法。

**交接条件：** 方案能够覆盖验收标准，实施任务具体可执行，未确定事项已显式标注。规划阶段不修改业务代码。

## 3. Generator Agent：实现

**输入：** 需求文档、`design.md`、`task.md` 和仓库约束。

**任务：**

1. 按任务顺序实施，保留用户已有改动，避免无关重构和依赖升级。
2. 实现代码；在有必要时添加能验证用户行为或业务规则的测试。
3. 缺陷修复遵循 `bug-fix/SKILL.md`，先复现并确认回归用例在修复前失败，再做最小修复。
4. 需要改变已有数据库结构时提供迁移，不通过删除数据库或清空数据代替迁移。
5. 运行与修改相关的检查，更新任务状态及实际变更记录。
6. 若发现方案不成立，回传规划阶段调整设计；不自行扩大需求范围。

**产出：** 代码、必要的测试与迁移、更新后的任务清单，以及实际执行的检查结果。

**交接条件：** 任务实现可供审查；未完成项、失败检查和限制已明确记录。当前用户要求忽略的测试文件不作为判断依据；后续测试策略遵循用户指令。

## 4. Evaluator Agent：评估

**输入：** 需求、设计、任务清单、实现差异和实现阶段的验证记录。

**任务：**

1. 对照验收标准独立检查实际行为，而非仅阅读实现阶段的结论。
2. 运行相关测试，检查正常流程、失败流程和重要边界条件。
3. 执行仓库实际提供的 lint、类型检查或构建命令；不存在的工具标注为未配置，不虚构检查通过。
4. 对 Web 功能进行浏览器验证，覆盖必要的页面交互、网络请求和状态恢复；无法执行时说明限制。
5. 审查 diff，检查是否有无关修改、接口不一致、数据迁移问题或敏感信息泄露。
6. 汇总问题，按路径、复现步骤、实际/预期结果和影响描述；将问题交回实现阶段修复，再验证受影响部分。

**产出：** 评估结论、逐项验收结果、实际执行的命令与证据、未执行项及剩余问题。

**交接条件：** 明确哪些标准通过、失败或未验证。必要检查失败或必需功能未完成时，不标记为可合并。评估角色以验证和审查为主，修复通过实现阶段完成。

## 5. 人工判断与合并

向用户提供可审查的最终结果：功能变化、关键差异、验证证据、迁移影响和剩余限制。由人工判断是否接受并合并。

未经明确授权，不自动合并、部署或执行破坏性数据操作。用户已授权的可逆实现和检查持续推进，不为例行步骤重复请求确认。

## 交接与记录原则

- 每阶段传递需求路径、当前工作区状态、修改范围、产出路径、验证证据和未完成事项。
- 需求变化先更新需求记录，再同步设计与任务；完成后更新项目架构及受影响的约束文档。
- 阶段按依赖顺序执行；如需并行工作，明确职责和文件边界，避免多个 Agent 同时修改同一文件。
- “已完成”“检查通过”和“可合并”必须有实际证据支持；不能把未执行的检查记为通过。
- 本流程文档的创建不意味着已经启动多个 Agent，也不代表自动获得合并或部署权限。
