# 注册登录前后端互通

- 提出日期：2026-10-01
- 状态：已实现并完成本地验收，待人工审查

## 背景与目标

现有后端已有注册、登录、查询当前用户和退出登录接口，前端注册与登录表单尚未提交请求。本次需求是连接前后端，实现注册创建数据库用户、登录返回对应用户，以及通过 Cookie 保持和恢复登录状态。

## 需求范围

### 注册与用户入库

- 前端读取用户名、姓名、密码，向 `POST /users` 提交 JSON `{username, name, password}`。
- 后端校验字段和用户名唯一性，使用 Argon2 对密码进行哈希，创建新的用户并提交到 SQLite 的 `users` 表。
- 注册成功返回 HTTP 201 和新用户信息，响应不包含明文密码或密码哈希。
- 前端提示注册成功并进入登录视图。注册不自动登录，用户随后使用新账号登录。
- 重复用户名或无效输入时显示明确错误，不创建重复用户，不跳转为登录成功状态。

### 登录与正确用户返回

- 前端读取用户名、密码，向 `POST /auth/login` 提交 JSON `{username, password}`。
- 后端按用户名查询用户并验证密码；只有验证成功才创建会话。
- 登录成功返回 HTTP 200 和该账号对应的用户信息：`id`、`username`、`name`、`created_at`、`height`、`position`。
- 返回的 `id` 必须与该账号在数据库中的用户 ID 一致，不返回固定用户或占位用户。
- 前端保存当前用户视图状态，展示当前用户信息，并切换到 Dashboard。
- 不存在的用户名或错误密码返回 HTTP 401，前端显示登录失败并保持未登录状态。

### Cookie 会话与登录恢复

- 登录成功由后端设置 `session_token` Cookie，使用 HttpOnly、Path=/，有效期 7 天，与数据库会话过期时间一致。
- 数据库 `auth_session` 表保存令牌的 SHA3-256 摘要、用户 ID 和过期时间，不保存原始令牌。
- 前端不读取 HttpOnly Cookie，不将令牌或密码保存到 localStorage。
- 页面初始化通过 `GET /auth/me` 查询当前用户；有效 Cookie 返回正确用户并进入 Dashboard。
- 缺少 Cookie、会话不存在、过期或关联用户不存在时返回 HTTP 401；前端回到未登录视图，不保留旧用户状态。
- 退出登录调用 `POST /auth/logout`，后端删除对应会话并清除 Cookie，前端清除当前用户状态。
- Cookie 的 SameSite、Secure 和请求凭据配置需与实际访问方式匹配；本地 HTTP 与生产 HTTPS 配置应区分。

### 前后端访问与交互

- 明确 API 访问方式：同源代理或配置指定来源的跨域访问。当前仓库尚未配置，两者选定一种实现即可。
- API 地址集中配置；采用跨域访问时，前端请求携带凭据，后端允许相应来源和凭据，不使用通配来源替代明确配置。
- 注册、登录、登录恢复和退出均处理加载、成功与错误状态；提交期间防止重复点击。
- 不在日志或控制台输出明文密码、Cookie 或原始令牌。

## 范围边界

- 本次实现账号注册、登录、Cookie 会话恢复与退出，不扩展投篮记录、训练查询或统计界面。
- 不新增第三方登录、密码找回、邮箱验证或用户资料编辑。
- 不将当前测试文件作为接口契约或需求依据。

## 验收标准

- [x] 前端注册成功后，数据库 `users` 表新增对应用户；刷新或重启后端后仍可用该账号登录。
- [x] 注册返回的用户 ID 与数据库记录一致，密码保存为可验证的 Argon2 哈希。
- [x] 重复用户名、过短密码和其他无效字段不会创建新用户，前端显示后端错误。
- [x] 使用正确用户名和密码登录，返回账号对应的用户并进入 Dashboard。
- [x] 分别使用两个不同账号登录，每次返回对应账号的 ID 和信息，不混用用户状态。
- [x] 用户不存在或密码错误时返回 401，不创建新的有效会话，前端不进入 Dashboard。
- [x] 登录响应设置 HttpOnly 的 `session_token` Cookie；数据库保存摘要而非原始令牌。
- [x] 刷新页面后，`/auth/me` 通过 Cookie 返回同一个用户，前端恢复登录状态。
- [x] 无 Cookie、无效或过期会话时，前端正确显示未登录状态并清除旧用户信息。
- [x] 退出后会话失效、Cookie 被清除；再次调用 `/auth/me` 无法恢复该会话。
- [x] 注册、登录和当前用户响应均不包含密码或密码哈希。
- [x] 实际选定的前后端访问方案可以完成 Cookie 接收与后续携带，不因跨域配置中断流程。
- [x] 表单显示加载和失败状态，防止重复提交；相关文档按最终实现同步更新。
