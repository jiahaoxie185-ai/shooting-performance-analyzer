# 新需求记录

每次添加新需求时，在本目录创建独立的 Markdown 文件，保留需求与实现状态的记录。

## 命名方式

使用 `YYYY-MM-DD-需求名称.md`；同一天的同名需求可添加序号，避免覆盖已有记录。

## 使用方式

1. 复制下方模板创建需求记录，填写目标、范围和验收标准。
2. 不确定的内容放入“待确认事项”，不要当作已确定需求。
3. 实现过程中更新状态、实际变更与验证结果。
4. 完成后同步更新受影响的 `../doc/项目架构.md` 和 `../rules/` 文档。

## 模板

```markdown
# 需求名称

- 提出日期：YYYY-MM-DD
- 状态：待确认 / 待实现 / 实现中 / 已完成 / 已取消

## 背景与目标

说明为什么需要该功能，以及用户希望达成的结果。

## 需求范围

列出本次需要实现的行为与明确的范围边界。

## 验收标准

- [ ] 可检查的用户行为或结果
- [ ] 边界情况与错误处理

## 影响范围

- 前端：涉及的页面、组件及路径
- 后端：涉及的接口、服务及路径
- 数据库：是否涉及表结构、数据迁移或查询变更
- 文档：需要同步更新的架构或约束文件

## 待确认事项

记录尚未明确的需求、选择或限制；无则填写“无”。

## 实际变更

实现后填写修改的路径、功能变化和必要的取舍。

## 验证结果

记录实际执行的检查及结果；未执行的检查明确标注。
```
