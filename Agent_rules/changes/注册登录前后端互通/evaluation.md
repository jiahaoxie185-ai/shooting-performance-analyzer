## 验收覆盖与限制

- API 已确认注册返回实际数据库用户、密码为可验证 Argon2 哈希、两个账号各自返回正确用户、失败登录不创建会话、摘要保存、会话恢复及撤销；注册/登录/恢复响应不包含密码或哈希。
- API 持久化验证包括关闭连接池后重新登录，以及独立 Python 进程注册后退出、另一个独立进程加载同一临时 SQLite 并调用登录接口，两个进程返回相同用户 ID。请求直接调用 ASGI，验证覆盖进程退出后的持久化，不把它描述为网络服务重启部署验证。
- Cookie Secure 开关已验证响应属性；生产域名、TLS、反向代理及实际生产 HTTPS 浏览器环境未提供，不声称生产部署验证完成。
- 关联用户不存在分支已独立实测：保留真实有效会话，模拟用户仓储返回 `None`，确认 `/auth/me` 返回 401“登录已失效”及 no-store。数据库仍开启外键约束，没有人为破坏数据库构造孤立记录。
- JavaScript 项目未配置 typecheck 脚本，不把 lint 当作类型检查。
- 构建在 dev 停止后完成，未与 dev 共用 `.next` 并发运行；没有为绕过字体下载修改字体、配置或应用代码。
- 浏览器验收由主代理在原生 Chrome 无痕窗口执行；实际结果见下面记录。构建虽然打印框架内置 TypeScript 阶段，但本仓库仍为 JavaScript 且没有独立 typecheck 脚本，未声称严格类型检查通过。

## 浏览器验收（主代理实测反馈）

真实 Next.js 同源代理与隔离数据库后端运行，主代理通过 UI 完成以下操作，并以页面截图确认用户身份：

| 步骤 | 实际结果 |
| --- | --- |
| 注册账号 A | 注册成功，转登录视图并显示成功提示 |
| 账号 A 错误密码登录 | 显示错误，停留登录视图 |
| 账号 A 正确登录 | Dashboard 显示验收用户甲及账号 A，用户 ID 与实际创建的账号一致 |
| 登录后浏览器刷新 | 恢复同一账号和同一用户 ID |
| 退出后再刷新 | 显示欢迎页，未恢复旧用户 |
| 重复注册账号 A | 显示“该用户已存在” |
| 注册账号 B 后登录 | 显示验收用户乙及不同用户 ID，没有混用账号 A 状态 |

上述完整 HTTP 代理交互和刷新恢复证明浏览器能够接收并后续携带 Cookie；Cookie HttpOnly、Secure 配置、摘要存储等属性由 API 验证提供独立证据，不把页面截图当作 Cookie 属性检查。测试账号和数据库限于隔离验证环境。

浏览器未模拟离线网络、过期会话和快速重复点击；相关失败及过期行为由请求模块/API 测试和禁用表单的代码审查覆盖，没有声称每个边界均进行浏览器实测。
