# 投篮训练 Web：需求与项目架构

## 项目目标

完成一个记录投篮命中率的 Web 应用。用户可以记录每次投篮的区域和命中结果，查询自己的单次训练、多次训练及对应命中率，并查看分区统计。

## 功能需求与验收标准

| 功能 | 验收标准 |
| --- | --- |
| 注册、登录与退出 | 用户可以注册和登录；刷新页面可恢复有效登录状态；退出后会话失效 |
| 创建训练 | 为当前用户创建一场训练，记录开始时间和可选备注 |
| 记录投篮 | 为指定训练添加投篮，保存区域、是否命中和投篮时间 |
| 结束训练 | 记录结束时间；结束后禁止新增投篮；重复结束保留首次结束时间 |
| 单次训练查询 | 根据训练 ID 查看当前用户的训练详情、投篮记录和统计 |
| 多次训练查询 | 查看当前用户的全部训练列表，并能进入各场详情 |
| 单次命中率 | 显示该场投篮次数、命中次数、总体命中率和分区统计 |
| 多次累计命中率 | 合并当前用户全部训练的投篮，计算总体命中率和分区统计 |
| 空数据状态 | 无训练时显示空列表；无投篮时次数和命中率均为零 |
| 数据归属 | 用户只能查询和操作自己的训练；后端验证归属 |

“多次训练”当前按用户全部训练累计统计定义。任意选取多场、按日期筛选、分页和导出尚未确定，不作为本阶段必需功能。

## 统计口径

- 总命中率 = 命中次数 / 投篮次数；无投篮时返回 0。
- 分区命中率 = 该区域命中次数 / 该区域投篮次数。
- 多场累计统计先合并投篮记录，再计算比例，不能直接平均各场命中率。
- API 的 `field_goals` 使用 0～1 的比例；前端乘以 100 展示百分比。
- 七个区域：`paint`、`left_midrange`、`right_midrange`、`top_midrange`、`left_corner`、`right_corner`、`top_three`。分区统计包含全部区域，无记录区域也返回零。

## 目录与职责

```text
main.py                   FastAPI 应用入口和路由注册
api/                      HTTP 路由、Pydantic 请求响应模型、依赖组装
application/              用户和训练业务流程、事务及密码哈希接口
domain/                   用户/训练/投篮实体、统计规则、仓储接口
infrastructure/           SQLAlchemy 仓储、SQLite、事务实现、Argon2
web/                      唯一前端目录，Next.js App Router + React
Agent_rules/doc/          项目架构与需求
Agent_rules/rules/        后端、前端和数据库约束
```

后端调用链：`main.py → api/router → application 服务 → 领域实体/规则与仓储接口`。`api/dependencies.py` 组装基础设施实现；`SqlAlchemyUnitOfWork` 管理仓储共用的数据库会话和事务。

前端入口为 `web/app/page.js`，根布局为 `web/app/layout.js`。业务组件位于 `web/components/`。前端通过 HTTP 调用后端，不直接访问数据库。

## 数据模型

```text
users ──< shooting_sessions ──< shot_attempts
  └────< auth_session
```

- `users`：用户身份、唯一用户名、姓名、密码哈希和创建时间。
- `shooting_sessions`：所属用户、开始/结束时间和备注。
- `shot_attempts`：所属训练、区域、命中结果和投篮时间。
- `auth_session`：令牌摘要、所属用户和会话过期时间。

## 现有接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/users` | 注册 |
| GET | `/users?username=...` | 按用户名查询用户 |
| GET | `/users/{user_id}` | 按 ID 查询用户 |
| POST | `/auth/login` | 登录并设置 Cookie |
| GET | `/auth/me` | 查询当前登录用户 |
| POST | `/auth/logout` | 退出登录 |
| POST | `/sessions` | 创建训练 |
| POST | `/sessions/{session_id}/shots` | 添加投篮 |
| POST | `/sessions/{session_id}/shots/batch` | 按出手数、命中数和区域批量追加投篮 |
| GET | `/sessions/{session_id}` | 单场训练详情及全部投篮记录 |
| POST | `/sessions/{session_id}/finish` | 结束训练 |
| GET | `/sessions/{session_id}/summary` | 单场统计 |
| GET | `/sessions/users/{user_id}` | 用户全部训练 |
| GET | `/sessions/users/{user_id}/summary` | 用户累计统计 |

训练详情接口复用 `ShootingService.get_session()`。批量接口调用新增 `ShootingService.add_shots()`，在一个工作单元中循环调用实体 `ShootingSession.add_shot()`，经仓储保存后统一提交，失败整批回滚。请求的 `attempts`、`made` 使用严格整数校验，要求 `attempts > 0` 且 `0 <= made <= attempts`，`zone` 必填；生成的逐球记录不代表真实出手顺序及时间。

## 当前实现与待完成项

- 已有后端注册、登录会话、训练写入、列表查询及统计逻辑。
- 前端已实现注册、登录、Cookie 会话恢复和退出登录。Dashboard 支持创建训练、列表进入单场详情、区域下拉选择、输入出手数及命中数批量追加、结束训练。结束后显示本场统计及今日累计命中率；今日统计按浏览器本地日期筛选后端返回的投篮记录，再合并数量计算比例。
- 当前后端投篮时间不带时区，Demo 按本地时间解释；跨时区部署时需统一时间存储与展示规则。
- 训练路由当前没有登录身份与数据归属校验，需要落实上述数据归属要求。
- 前端使用 Next.js 同源 `/api/:path*` 代理转发到后端，`BACKEND_URL` 默认 `http://127.0.0.1:8000`。浏览器请求统一携带 Cookie 凭据，不需要额外 CORS。配置变化后重启或重新构建前端。
- 认证 Cookie 为 HttpOnly、Path=/、SameSite=Lax、7 天；后端 `COOKIE_SECURE=true` 启用 HTTPS Secure 属性，本地 HTTP 默认 false。认证响应禁用缓存。生产 HTTPS 尚未部署验证。
- 数据库初始化脚本仅创建缺失表，不迁移已有表结构。
- 后端依赖清单、运行时版本要求尚未在仓库中声明；不从本地虚拟环境推定项目版本要求。
- 按用户要求，当前测试文件不作为架构和实现判断依据。
